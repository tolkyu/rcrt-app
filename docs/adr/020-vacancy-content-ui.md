# ADR-020 — Vacancy content editor and full-card viewer

- **Status:** Implementable contract for focused security/UX review; no policy change.
- **Date / basis:** 2026-11-19; VAC-01/VAC-08, D75/D92/D117/D133; [ADR-018](018-vacancy-content-editing.md), [ADR-019](019-vacancy-content-read.md), [UX](../ux/wireframes/vacancy-content-edit.md), [F10](../ux/ui-foundation.md).
- **Evidence:** baseline `b0e7c3e`, full CI `44474819422` green. GET/query/loader and F10-A renderer/adapter now exist locally; their final reviews remain implementation gates.

## Decision and entry

Use `/vacancies/[vacancyId]/content/edit`; preserve author-only `/vacancies/[vacancyId]/edit`. One two-field form, no general-edit fields. The full card alone shows the viewer and the UX-defined edit link; list/preview neither imports editor/viewer runtime nor fetches documents.

Card and editor use existing `loadVacancy` and `loadVacancyContent` with `requireSession`, per-request QueryClient and `HydrationBoundary`. Start independent metadata/content loads together with `Promise.all`; existing request-cache reuse avoids duplicate calls. Seed `queryKeys.vacancy(id)` and `queryKeys.vacancyContent(id)` with their **distinct** DTOs, dehydrate successful entries only. In the card, content 5xx is a retryable section error; 404 makes the full card unavailable and removes content. In the editor's layout, resolve hidden/missing content before the loading boundary for a real HTTP 404; recoverable failures get a retry state, never writable empty documents.

The editor layout provides route-scoped messages through a small `vacancyContentClientMessages` selector, including `common`, `form`, `states`, `richText` and exact content/error namespaces. Do not load the entire create-form namespace. The card needs only its content labels/action/error copy, already under `vacancies`. Keep common toolbar copy out of shell-wide namespaces.

Both surfaces use one `vacancyContentQuery(id)` observer per mounted surface for the two documents. Form activation requires a successful entry revalidation (the query has staleTime/gcTime zero), then `canEditContent:true` and OPEN/ON_HOLD from **that same read**. No role-name, creator, detail-cache version or urgency shortcut. Existing pure-Admin MFA redirect and active mixed-role grants remain unchanged; do not add a privileged-page gate that suppresses independent lower grants.

Direct navigation with readable content but false eligibility shows the appropriate locked/read-only state and back-to-card action, with no writable editors. Own DRAFT links go to the existing draft flow; closed rows retain read-only viewing. D133 requires existing authorized reopen before editing FILLED and never allows reopening CANCELLED. No new owner decision is needed.

## F10-B shared component contract

`RichTextEditor` is a lightweight client shell, dynamically loading `rich-text-editor-runtime.tsx` with SSR disabled; only the runtime/toolbar import installed Tiptap 3.34.0 extensions. Reuse `LoadBoundary`, reserved-height skeleton and inline retry. Loading/error/unmount reports not-ready and blocks save; chunk retry must reset the failed boundary/import attempt rather than merely rerender the rejected promise. No editor import in `RichTextView` or the preview path.

Exact shared props: existing `FieldControlProps` plus `initialDocument: RichTextDoc | null`, `resetKey:string`, `disabled:boolean`, `onChange:(result:EditorDocumentResult)=>void`, `onReadyChange:(ready:boolean)=>void`. `FormField` owns labels/errors; use its group layout for the contenteditable control so the actual label supplies aria-labelledby. Forward control ID/ARIA to the focusable textbox root with aria-multiline; toolbar buttons are type button. The shell owns no vacancy, query, mutation, Clear intent or permission policy.

- Initialize via existing `toEditorDocument`; report ready only after runtime creation/validation. Initial NULL displayed as an empty paragraph does **not** emit a user edit or turn NULL into a document.
- Every actual document update, including invalid/oversized content, emits `parseEditorDocument(editor.getJSON())`. Consumers must handle both discriminants; never retain a previous valid document as the current value after an invalid result. Keep invalid editor input only in mounted memory, never logs/storage. Paste uses the installed allowlisted extensions; adapter/schema remain the canonical validation boundary.
- Honor external document replacement only when `resetKey` changes through an explicit baseline adoption, and only if canonical documents differ. Compare both target and live content after the same Tiptap schema normalization and `parseEditorDocument` pass; stripped default attributes and mark rank/order must not trigger setContent. Ordinary render/query/callback identity changes never call setContent or remount Tiptap. Preserve cursor/selection through typing, validation, background reads and unrelated metadata refreshes.
- Toolbar: F10-labelled bold/italic/headings 1–3/lists/link/hard-break controls, correct pressed states, safe link validation with the shared schema, keyboard formatting/IME intact. Link entry reuses existing `Dialog`, `Input`, `Label` and `Button`, preserving editor selection and restoring focus; no browser prompt. No unsupported extension, HTML injection, silent valid fallback or JSON-facing product copy. Use F10/UX mobile and reduced-motion rules unchanged.

## Published form state and mutation

Keep a saved `VacancyContent` baseline initialized from GET, separate from the latest authoritative `VacancyContentRead` access result and local field intents. Each field has a discriminated intent: unchanged, replacement carrying the **whole** `EditorDocumentResult`, or explicit clear. A replacement marked invalid remains dirty and blocks the entire save; serialize only a valid replacement document, NULL for clear, and omit unchanged keys. Validate the final strict `updateVacancyContentSchema` before dispatch; never parse failure into omission.

Clear is form-level intent, not an editor deletion event: retain the mounted pre-clear buffer (including invalid input) while showing the cleared state and «Скасувати очищення»; undo restores that exact buffer. A deliberate editor deletion remains an empty document. After a saved clear, adopt NULL and discard the retained buffer. Background reads never cancel Clear or undo it implicitly.

Reuse `FormPageLayout`, `FormField`, `Button`, `FormAlert`, `VacancyFormError` and `useSubmissionLock`. Save requires eligible current access, both runtimes ready, dirty valid intents and no pending/stale/reload/access gate. Set the ref lock **before** the first await; freeze field/Clear/undo actions while sending. Ctrl/Cmd+Enter uses the same guard outside IME; ordinary Enter edits text. The leave guard protects Cancel/back and tab close while dirty/pending; disable the explicit Cancel action during sending. Forced navigation cannot be made transactional: late callbacks must check mounted identity/generation.

Cancel in-flight content reads and mark the submission generation before dispatch; ignore older completions. Send PATCH with baseline version and only dirty keys using `apiRequest` plus `vacancyContentSchema`; no optimistic document write. On confirmed success, adopt both canonical returned documents/version/time as the clean local baseline and announce the inline success/no-op state. Do not fabricate GET status/eligibility or overwrite its cache with PATCH's shorter DTO. Invalidate the vacancy prefix and list prefix with existing `refreshVacancy`, refetch content and block the next save until fresh access is known. Preserve the cursor when canonical content matches; explicit reload or a necessary canonical replacement may advance resetKey. Never reset to an older GET revision that was in flight before success.

| Outcome                                      | Required behavior                                                                                                                                                                                                                                     |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Background read, same baseline version       | Refresh access metadata only; retain all local field state/selection.                                                                                                                                                                                 |
| New version / `409 STALE_STATE`              | Preserve edits; mark stale and block repeat save. Explicit reload uses existing `ConfirmDialog`/discard copy when dirty; only confirmed, successful GET adoption resets editors. Do not change the shared leave-guard API to implement this callback. |
| Closed status / `409 VACANCY_CONTENT_LOCKED` | Block writes; keep selectable local text only while read access remains valid. Refresh content/status; no automatic reopen or edit replay.                                                                                                            |
| PATCH 403                                    | Stop saving and refresh GET. Read retained + false → read-only/permission-changed state; true from independent mixed-role grant still requires deliberate retry and current-version baseline. Never silently rebase dirty edits.                      |
| 400 / 413                                    | Keep invalid input; translate field codes, focus summary/editor and block until corrected. No technical JSON counter or raw server issue/input text in the product.                                                                                   |
| Network / 5xx / 429                          | Preserve input and show inherited persistent retry/wait feedback. Ambiguous save outcome requires an authoritative GET check; version alone cannot prove who wrote. Do not announce success, auto-replay or silently replace dirty input.             |

## Access loss and identity boundary

On GET/PATCH 401 or content GET 403/404 (GET 403 = read grant lost; shown as unavailable, SEC-F1), render no cached documents/editors in that render, cancel pending content requests, remove the content query, clear baseline/invalid buffers/Clear undo state, release the leave guard and follow existing session/MFA/unavailable flow. An observer must not keep refetching itself after terminal denial; unmount it behind the unavailable state. Permission-driven removal is not a discard choice. On readable 403 retain only what the successful GET still permits.

Minimal identity change: in existing `app/(app)/layout.tsx`, place `key` on the existing `AppProviders` wrapping `HydrationBoundary`; derive it from `ctx.auth.userId` and verified `ctx.identity.sessionId`, both available from `requireSession()`. The same identity keeps its key through navigation, role refresh and MFA step-up; another user/session remounts the existing QueryClient/component tree before hydration. No provider refactor or tokens in props. A terminal 401 also cancels/clears the old client before redirect/refresh. Ignore late completions after identity/generation change; existing page/session guards remain mandatory. Revocation observation is ADR-019's next-read/focus/reconnect behavior, not instant remote erasure.

The full-card host passes lightweight header/content slots into `VacancyOverview`; the shared overview only renders the slots and does not import content query/editor modules. Its query/denial boundary gates the whole card when content proves it unreadable; do not leave stale metadata and actions behind a content 404.

## Verification and remaining dependencies

Engineer unit/component tests must exercise invalid→save prevention, NULL/empty/clear/undo, initial-not-ready/chunk failure/retry, cursor-preserving updates, duplicate press/IME, stale/closed/race outcomes, shorter PATCH vs GET caches and late-result denial/identity cleanup. Real-browser tests cover allowed/read-only/foreign/private roles, mixed MFA, confirmed discard/reload, 401/404 eviction and identity switch, 403 retained reads, unassignment/status change, safe paste/links and keyboard/mobile/footer behavior. Do not substitute mocked adapter tests for Tiptap runtime behavior.

Blast-radius proof: ACCESS runs focused provider identity tests (same user/session retains client through MFA/role refresh; sign-out/new user/new session cannot reuse it) plus existing `auth.spec.ts`, `mfa.spec.ts`, `profile.spec.ts`. CARD runs existing `vacancies.spec.ts`, `vacancy-share.spec.ts`, `vacancy-assignment.spec.ts`, `vacancy-status.spec.ts` and affected card/preview E2E; PAGE adds `vacancy-content-edit.spec.ts` and confirms existing `vacancies-edit.spec.ts` / `vacancies-edit-access.spec.ts` stay on the draft path. D117 later runs all changed create/draft screen specs. Do not run a full local suite as a substitute for this matrix or duplicate passing CI (D129).

Before UI implementation: focused security and UX contract review. After each slice: typecheck/lint/touched tests and all E2E specs of changed shared screens; separate code review, security/QA for access/PII, UX review, and performance/bundle review for card and editor. F10 must remain outside initial card/list bundles; measure rather than assume the 180 kB budget. D125 captures only new screens/states at V-block end, plus required phone checks. No tests/builds/install/commit/push in this design task.

No unresolved product-policy decision: D133 is settled. Remaining technical dependencies are final GET/F10-A approval, F10-B runtime and the bounded tasks above. D117 create/draft adoption remains required follow-on work and must be reported until delivered; it is not covered by the published form alone.
