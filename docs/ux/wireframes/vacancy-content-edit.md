# Vacancy content editing — follow-on UI design

Preparation only · 2026-11-18 · VAC-08, D75/D78/D92/D133 · STORY-VAC-01-2a · [ADR-018](../../adr/018-vacancy-content-editing.md). No UI implementation, new endpoint or owner policy is authorized by this document. The API slice remains independently deliverable.

## Smallest surface and entry

- One dedicated page for two fields, using `FormPageLayout`, `FormPageHeading`, `FormPageFooter`, `FormField`, `Button`, `FormAlert`, `VacancyFormError`, `SectionError` and the existing leave guard. Single form column, max 720 px; no readiness rail, publish controls or operational fields. [ADR-020](../../adr/020-vacancy-content-ui.md) chooses `/vacancies/[vacancyId]/content/edit`; author-only draft `/edit` remains separate.
- Detail card, «Опис і вимоги» heading row: outline «Редагувати опис і вимоги» at the row end (44 px target; the row reserves 44 px in every state, so the card does not shift), only when the authoritative content capability and `OPEN`/`ON_HOLD` permit it. Do not infer eligibility from role names, creator identity, read access or urgency controls. No new list/preview entry in this smallest UI slice.
- Effective allowed actors: assigned Recruiter, own Team Lead, scoped Head Recruiter/Admin, and applicable custom/mixed grants per ADR-018. HR/Head HR reading rights alone do not qualify. Existing Admin MFA behavior remains authoritative.
- `FILLED`/`CANCELLED`: no content-edit entry. Reopening remains an existing authorized `FILLED` action, never an editor action; `CANCELLED` cannot reopen. Draft links retain the current draft flow, including immutable cancelled drafts.

## Read and editor dependencies — not yet ready to build

- **Read implemented; final review pending:** [ADR-019](../../adr/019-vacancy-content-read.md) GET/query/request loader now return both nullable documents/version/status and effective `canEditContent`; existing `VacancyDetail` stays unchanged. ADR-020 defines UI hydration, current-entry revalidation and denial cleanup. Never submit PATCH to read or treat missing document fields as empty content.
- **F10-A exists; F10-B pending:** pure `RichTextView` and typed editor document adapter are implemented locally; final reviews remain gates. Installed Tiptap 3.34.0 supplies the forthcoming lazy shell/runtime and labelled toolbar per [ui-foundation §F10](../ui-foundation.md)/ADR-020. Every invalid edit must block saving, including after a previously valid value. Reuse accessible dialog primitives for links, never a browser prompt; no textarea interim or HTML injection.
- Display the loaded description/requirements in the existing detail card content area through F10 `RichTextView`; no editor dependency on a read-only card. Reuse future shared read data rather than add a second content fetch per field. Empty read-only sections show «Опис ще не додано» / «Вимоги ще не додано» after a successful read only.

## Loading, failure and concurrent changes

| State                                        | UI and recovery                                                                                                                                                                                                                                                                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Initial loading                              | Heading/labels/editor-shaped skeletons reserve final geometry; footer Save disabled, loading announced. Do not render writable blank documents before the read resolves. Editor chunk failure shows inline retry in its reserved slot; no save before schema/editor readiness.                                                             |
| Read failure                                 | `SectionError` with «Повторити», no writable form or fake empty state. Existing 404 page for unavailable/out-of-scope resources; do not reveal content or roles.                                                                                                                                                                           |
| Validation / 400 / 413                       | Keep input; field error linked by `aria-describedby`, summary links focus the relevant editor. Announce first error once. Invalid document/oversize payload cannot be fixed by automatic retry; show the inherited translated error and allow editing.                                                                                     |
| Network / 5xx / 429                          | Keep edits, unlock failed request, persistent alert; confirmed refusals allow a deliberate retry of current edits. For 429 use existing wait feedback. An ambiguous network/save outcome first needs the approved GET/version reconciliation without replacing dirty input; do not claim a write failed or succeeded without evidence.     |
| `409 STALE_STATE`                            | Persistent warning above fields; preserve typed values, block repeat save against stale version. «Завантажити актуальну версію» requires the existing discard confirmation when dirty. Reload only by explicit consent; no force-save, auto-merge or silent overwrite. Other status/team/urgency changes can legitimately make this stale. |
| `409 VACANCY_CONTENT_LOCKED` / status closes | Stop saving, announce locked state; keep local typed text selectable while read access remains valid, offer «До картки вакансії». If `FILLED`, explain existing reopen requirement; if `CANCELLED`, explain no further editing. Never reopen automatically or replay edits after reopen; a fresh authorized read is required.              |
| Assignment/grant removed                     | Authoritative denial hides edit controls and stops submission. Independent mixed-role grant may still permit editing; rely on fresh capability, not “removed recruiter” alone. On 403, show «Право редагування змінилося» and refresh approved access state. Do not keep displaying protected documents if read permission is lost.        |
| Deactivated / session / MFA                  | Use existing session/MFA flow; no automatic write replay after reauthentication. Hide protected form when access ends. Unknown/deleted/out-of-scope 404 follows existing unavailable screen; no details about the hidden vacancy.                                                                                                          |

- Read failure keeps the static heading and back link, without vacancy number or title. The 404/denied state stays unchanged.
- «Очистити» is unavailable only while that field's editor chunk has failed, with the reason «Очистити можна після завантаження редактора.»; a successful retry restores it. It stays available for an invalid stored document, because it is the way out of that state.
- A pristine «Зберегти зміни» shows «Немає змін для збереження»: tooltip with hover, visible text on touch.
- Toolbar, typography and save-result placement follow [the gallery review](../review-phase-2-content-gallery.md) (B1–B4, D1, D2). The save status sits in the sticky footer; a failed save scrolls the alerts into view without moving focus.
- Rich-text H2 is `text-lg` (18/28, 600), documented in design system §2 (P12).

## 390 px, keyboard and motion

- 16 px gutters, one column; editor text ≥16 px, selectable content, zoom enabled. Toolbar wraps into labelled controls without horizontal page overflow; touch targets ≥44 px. Long vacancy titles and translated labels wrap; footer buttons use natural height (minimum 48 px), Save full width and last when wrapping.
- Reuse the sticky footer above BottomNav with safe-area spacing and measured content clearance. Keep the final editor line/validation visible when the keyboard opens; avoid a nested full-page scroll container. Hardware-phone keyboard, safe-area and footer checks remain required at implementation.
- Natural tab order: back → fields/toolbars → Cancel → Save. Toolbar names/pressed states per F10; Enter inserts editor content, not a save. Ctrl/Cmd+Enter saves only through the guarded form shortcut when valid and outside IME composition; editor formatting shortcuts remain intact. Page Esc does not discard; discard dialog Esc returns to the initiating control and retains edits.
- Motion gate: page navigation, editor typing, validation, reload and inline save feedback are functional/high-frequency changes: **no animation**. Reuse existing leave-confirmation tokens only (`motion-modal` desktop / `motion-sheet-up` mobile); keyboard-opened confirmation is instant, reduced motion uses the existing opacity-only behavior. No new duration, library or height animation. Skills: `emil-design-eng`, `animate` (gate only), `mobile-native`, TypeScript inventory rules.
