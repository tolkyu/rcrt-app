## 2. Foundation slice

### 2.1 Principles

- Build only what S3 (create/edit form, «Чернетки» chip, draft actions, cancel with reason, delete, 409 toast) needs, plus tokens and shell fixes that touch only shared files.
- A screen that S3 modifies (vacancies list filter bar, preview header) **does** adopt the new components in S3. Screens S3 does not touch (positions, settings, profile, audit, users) keep their current markup until the retrofit pass.
- Each task ≤ ~400 lines of diff, ships with its section in the dev gallery and a Vitest/axe check; sizes below are estimates.
- Bundle: initial JS must not grow by more than **+1.5 KB gz per task** (`pnpm perf:size`). Heavy Radix parts (Select, Popover, Tooltip) and Tiptap load lazily through the existing deferred pattern (`useDeferredMenu`/`LoadBoundary`): a static trigger renders at once, the chunk loads on hover/focus/press.

## 3. Motion spec

Tokens and the CSS live in `design-system.md` §8. Rules here are the decision record.

### 3.1 Decision matrix (frequency gate → purpose → spec)

| Interaction                                                                     | Frequency        | Animate?             | Purpose             | Spec                                                                                                                          | Reduced motion                      |
| ------------------------------------------------------------------------------- | ---------------- | -------------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| Button / chip / icon button press                                               | very high        | yes, tiny            | feedback            | `transform: scale(.97)` on `:active`, 120 ms, `--ease-out`; `touch-action: manipulation`                                      | no scale                            |

### 3.2 Rules

- **Properties:** `transform`, `opacity` (compositor). Colour (`background-color`, `color`, `border-color`) allowed for hover/press. Never `width`, `height`, `margin`, `padding`, `top`, `left`; never `transition: all` (scan test in F1). Use the individual `translate` / `scale` properties (Tailwind 4 emits them) so keyframes and centring do not fight.
- **Curves:** only `--ease-out`, `--ease-in-out`, `--ease-drawer`. Overriding `--ease-out` inside `@theme` makes every existing `ease-out` utility strong at once. No `ease-in` on UI. Never animate from `scale(0)`: minimum `scale(.95)` + opacity.
- **Durations:** UI ≤ 300 ms. Exits are faster than enters (asymmetric). Press 120, tooltip 125, popover 160/120, dialog 200/150, drawer 240/180.
- **Radix exits = keyframes** (finding 3). Transitions only for non-Radix elements (hover, press, Sonner, future accordion). Popovers use `transform-origin` from the Radix variable; modals stay centred.
- **No CSS-variable-driven child transforms** on a shared parent; set transforms on the element itself. No blur masks unless a crossfade looks wrong in the slow-motion check.
- **Reduced motion** (replaces the blanket 0.01 ms rule): keyframes read `--motion-scale` and `--motion-shift`, which the media query sets to `1` and `0`; only opacity remains (≤ 120 ms). Press scale off. Check with DevTools emulation.
- **Touch:** all hover effects only inside `hover:` (Tailwind 4.3 already compiles it to `@media (hover: hover)`); do not hand-write `:hover`. `:active` is the touch press feedback. Rows and cards (large surfaces) get a colour change on `:active`, not a scale.
- **Review step:** every task is played at 3× duration (DevTools) once and re-checked the next day, per the skills. Note the result in the task PR.

## 6. Accessibility and mobile (TL flows)

- **Focus:** Dialog/AlertDialog trap and restore focus; menus opened by keyboard focus the first item (existing `menuAutoFocus`); Select/Combobox follow APG, with type-ahead and Esc returning focus to the trigger; focus ring `2px --ring`, offset 2, never removed.
- **Disabled with reason:** use `aria-disabled` (stays focusable) plus `aria-describedby`, not `disabled`. On touch the reason is visible text under the control, because tooltips do not exist on touch.
- **Labels and errors:** every control has a visible label; error text is linked and not colour-only (icon + text); required marked with `*` and announced; summary «Виправте N полів» on submit, focus to the first invalid field.
- **Targets:** ≥ 44 px on touch (`pointer-coarse:` variants), ≥ 32 desktop; chips, `⋯` buttons, options, sticky CTA included.
- **Contrast:** new `*-subtle`/`*-text` pairs must pass AA in both themes (axe in the gallery, §7); focus and borders ≥ 3:1 (`--input`).
- **Mobile forms:** inputs 16 px (no iOS zoom), `inputMode`/`enterKeyHint`/`autocomplete` set; `viewport interactive-widget=resizes-content` so the sticky bar rides above the keyboard; `100dvh`, not `100vh`; safe-area padding on bar, sheets and toasts; bottom sheets (not centred dialogs) below 768 px; primary action last (thumb zone); no hover-only controls.
- **TL flows relevance:** the same Dialog bottom sheet, `ConfirmDialog`, `DisabledReason` (visible helper text) and `StickyActionBar` serve accept/decline, reschedule, interview result and probation close later; S3 proves them first.
- **Hardware check:** sticky hover, tap highlight, safe areas, keyboard and overscroll cannot be verified in emulation. Before the owner report, test F1/F8/F9 on a real iPhone and a mid-range Android (the orchestrator asks the owner to do a 5-minute check, or QA uses BrowserStack-like device if available).
- **Reduced motion:** emulate `prefers-reduced-motion: reduce` once per component; dialogs still open and close (opacity), nothing slides.
