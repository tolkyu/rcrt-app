## Should fix

1. app/globals.css:239 `overscroll-behavior: none` on html also sets the x axis. On macOS Chrome/Safari this disables the two-finger swipe back/forward gesture; the stated reason (pull-to-refresh) is y only. Fix: `overscroll-behavior-y: none;`.
2. app/layout.tsx:27-38 `viewportFit: cover` makes the page draw under the notch and rounded corners in landscape, and nothing pads left/right (grep safe-area shows only bottom insets). Fix: in `@layer base` add `body { padding-inline: env(safe-area-inset-left) env(safe-area-inset-right); }` (fixed inset-x-0 bars such as components/shell/bottom-nav.tsx:27 need the same), or record that landscape is out of scope for TL flows. Verify on a real iPhone (ui-foundation section 6).
3. app/globals.css:236 the transparent tap-highlight reset removes the only touch feedback on links, sidebar/bottom-nav items, settings-nav items and list rows, and no `:active` colour exists for them (only Button has one). design-system 3.2 requires `:active` colour on rows/cards. Fix: add `active:bg-surface-muted` to components/shell/sidebar.tsx:79, bottom-nav.tsx, components/settings/settings-nav.tsx:40 and the vacancies row, or land the reset in the task that adds those states.
4. app/globals.css:284-418 motion keyframes and `@utility motion-*` (pop, tooltip, modal, sheet-up, sheet-side, fade) have no consumer (grep for motion- in components and app finds none outside the CSS). Plain @keyframes are always emitted, utilities are tree-shaken, so nothing proves the CSS works until F8; a typo in data-instant or the popper origin variable would surface late. Spec F1 asks for a Motion gallery section and it is missing (app/dev/ui/page.dev.tsx:21-23 renders Tokens, Badges, Buttons). Fix: add components/dev-ui/motion-section.tsx with one static data-state demo per utility (and a data-instant instance) so the 3x slow-motion review of design-system 8.4 is possible.
5. components/theme/theme-provider.tsx:35-41 and app/layout.tsx:27-38 have no test. themeColorFor is covered, but nothing asserts generateViewport() returns viewportFit cover, interactiveWidget resizes-content and both media entries, nor that setTheme rewrites the metas. Fix: unit-test generateViewport with a mocked next/headers cookie (dark cookie gives dark colour in both entries; no cookie gives one colour per scheme); cover the meta rewrite in jsdom or in the QA E2E (state which).
6. /login JS budget (179.47 / 180 kB, 0.53 kB headroom). The only client bytes this diff adds are in theme-provider.tsx (themeColorFor, THEME_COLORS from lib/theme.ts:13-27, and the DOM loop); estimate 0.1-0.25 kB gz, THEME_COLOR_MEDIA should tree-shake. CSS, dev-ui and the .dev.tsx page are outside the JS entries. Fix: run pnpm build and pnpm perf:size before commit and record the number in PROGRESS; if headroom is under 0.3 kB, shrink the loop (compare meta.media with THEME_COLOR_MEDIA.dark) or load the rewrite lazily from the toggle.

## Nit

1. tests/unit/vacancies/urgent-contrast.test.ts:116,125 it.each over light/dark ignores its parameter in the primary-foreground test (plain hex, no theme), so the same assertion runs twice and the title is misleading. Drop the it.each.
2. Same file: "every subtle fill is declared for the %s theme" is redundant with the contrast tests (token() already throws when a pair is missing). Remove.
3. tests/unit/ui-motion-rules.test.ts:12 scans components/ only; spec says no transition-all, ease-in or scale-0 in app code. Add app/ and globals.css (ease-in).
4. tests/unit/ui-motion-rules.test.ts:27-37 asserts the literal Button class string, so a harmless reorder fails it. Acceptable until the Playwright computed-style check lands, then delete.
5. components/ui/button.tsx:7 select-none is redundant with the global button rule (globals.css:274). Hover colour also moved to the strong ease-out; the skill and spec 3.1 say ease for colour changes. Minor; mention in F2.
6. components/theme/theme-provider.tsx:40 includes('dark') couples to the media string; compare with THEME_COLOR_MEDIA.dark.
7. app/layout.tsx:27 and :46 parse the theme cookie twice; cookies() is request-memoised so no cost, but a shared helper would remove the duplication.
8. Under reduced motion animate-pulse (components/settings/role-matrix.tsx:163) now loops forever; the old blanket rule collapsed it. Opacity only, but add motion-reduce:animate-none. Sheet slides (components/ui/sheet.tsx:14-17, no opacity part) become a 200 ms no-op that still delays Radix unmount; F8 fixes it.
9. messages/uk.json devUi.badges.info is unused. devUi.buttons.ariaDisabled labels an aria-disabled button "with reason" but shows no reason; rename until F2 adds DisabledReason.
10. components/dev-ui/badges-section.tsx:6-8 hand-rolls pill classes that F2 turns into Badge; replace in F2.
11. The gallery has no theme switch, so light/dark screenshots depend on the cookie or colorScheme emulation; the intro text implies both themes are viewable.
12. --brand-fill is a new token not in design-system 1.1; add it to the doc with a line on why the dark fill stays #5558EF.
