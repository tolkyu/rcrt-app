The page gates on `requirePrivilegedSession` plus `hasAnyGrant` → `notFound()` (`page.tsx:30-33`), and `getAuditActor` runs only after that.                                                                                        | Pass                             |
| Denied tests           | Integration (`settings-audit.test.ts` `it.each`): a Recruiter gets 404 `NOT_FOUND` and an aal1 Admin gets 401 `MFA_REQUIRED`, for both `listAuditActors` and `getAuditActor`. | Input                  | `.strict()` query (`lib/schemas/audit.ts:129`). `q` is trimmed and 2–100 chars. `cursor` is `z.uuid()`. `limit` is an int 1–50. A repeated `q` becomes an array and gets 400. The problem body returns only path and code, never the input. `actorId` on `/audit` accepts only a UUID or the literal `system` (`SYSTEM` gets 400).                                                                          | Pass                             |
| LIKE injection         | `userSearchMatch` escapes `\ % _` to `\$&`, and the pattern is a bound parameter. PostgreSQL's default LIKE escape is `\`, and `standard_conforming_strings` does not matter for a bound value. Test: `q=%_<marker>` returns `[]`. No `sql.raw`.                                                                                                                                                            | Pass                             |
| Cursor tampering       | `afterUser` binds `${afterId}::uuid` in a PK subquery. An unknown UUID makes the subquery NULL, so the row comparison is NULL and the page is empty. There is no error and no existence oracle beyond what Admin already sees. Reusing a cursor with a different `q` just continues the keyset. The cursor contains only an id, never a name (comment on `schemas/audit.ts:123`).                           | Pass                             |
| Query cost             | Each actor request runs one statement and returns at most `limit+1 ? 51` rows. Keyset ordering has the existing `app_user_list_idx`; substring search remains a bounded-output scan of the staff table. `actorId=system` binds actor NULL and excludes `auth.login_failed` with no entity. Existing indexes support these filters; actual plan choice depends on dataset size (see the performance report). | Pass; no endpoint/load P95 claim |
| `listUsers` refactor   | Shared search, keyset and ordering preserve the full directory behavior and its authz. Only `listUserOptions` adds `activated_at IS NOT NULL`, so the picker includes previously activated users, including deactivated users, and excludes never-accepted invitees.                                                                                                                                        | Pass                             |
| Output minimisation    | Picker DTO = `{id, fullName, isActive}`. No email, roles, invite state or session information is returned; names are rendered as React text.                                                                                                                                                                                                                                                                | Pass                             |
| Client                 | No `dangerouslySetInnerHTML`. Query text remains in in-memory TanStack Query (no persister). SessionStorage contains only `chunk-reload-at`; no search, name, email or actor id is persisted. While a new search is debouncing or uses placeholder data, stale options and stale-query pagination are suppressed, so Enter cannot choose a previous result.                                                 | Pass                             |

## SEC-AAF-01 resolution

Implemented in `lib/load-or-reload.ts`: one guarded reload within a 30-second window; subsequent failures reach the error boundary. Success does not reset the shared window. Storage errors fail safely by rethrowing the original loader error. The marker is a timestamp only. Existing inherited search-log handling and per-user search rate limiting remain T9 follow-ups (SEC-AAF-02/03), not new blockers for this slice.
