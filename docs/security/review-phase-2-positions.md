# Security review — Phase 2 position catalog (ADR-013, T1 + T2)

Date: 2026-11-09. Scope: uncommitted `phase-2` tree — `docs/adr/013-position-catalog.md`, migration `0012_position_catalog_writes.sql`, `server/authz/{permissions,roles,scopes}.ts`, `app/api/v1/positions/**`, `server/services/position.ts`, `server/repositories/position.ts`, `lib/schemas/position.ts`, audit/event/`map-error` additions, audit viewer widening, Newman cases. Static review only (no tests or builds run); the T3 UI page is not yet written and is out of scope.

**Verdict: approved for commit with one Medium to resolve or verify first (SEC-POS-01) and three Low hardening items to land before T3 ships.** No Critical or High. Authz, 404/403 uniformity, Finance and MFA behaviour, CSRF, mass assignment, locking, grants and audit contents all hold.

## Findings

| ID         | Severity | Evidence                                                                                                                                                                                                                                                                                       | Fix / disposition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------- | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SEC-POS-01 | Medium   | `server/db/schema.ts:655` (`position_name_uq` on `lower(name)`); `lib/schemas/position.ts:14-19` (no Unicode normalisation); `docs/perf/plan.md:499` (R6: Supabase `LC_CTYPE` may be `C`). Integration tests run on the stock Docker locale, so `positions.test.ts:461-479` cannot catch this. | The unique index is the only duplicate arbiter, and `lower()` follows the database `LC_CTYPE`. Under `C`, Cyrillic is not folded: «Афілейт Лід» and «АФІЛЕЙТ ЛІД» become two positions (and two ROUTE-02 routing groups). Also, «й»/«ї» exist as composed and decomposed forms that `lower()` never equates. Fix: (1) confirm `SHOW lc_ctype` on the Supabase project; (2) make uniqueness locale-independent: schema `.transform(v => v.normalize('NFC'))` plus a stored `name_key` (app-computed `toLocaleLowerCase('uk-UA')` of the collapsed name) with the unique index on `(vertical_id, name_key)`, or at minimum `lower(name COLLATE "uk-UA-x-icu")` in the index; (3) add an integration test with NFD «й» and an upper-case Cyrillic duplicate. 0012 is untracked, so fold the change into it if it was never applied outside local DBs, otherwise 0013. |
| SEC-POS-02 | Low      | `lib/schemas/position.ts:11-19` rejects only `\p{Cc}`; `.trim()` is the only whitespace handling.                                                                                                                                                                                              | Names may contain zero-width and bidi characters (`\p{Cf}`: U+200B, U+202E), U+2028/2029, private-use code points, and runs of inner spaces. These give invisible look-alike duplicates, spoofed labels in pickers and in the Admin audit viewer, and fragmented routing groups. Fix in `positionNameSchema` (shared by create and PATCH, idempotent on the service's second parse): NFC, collapse `\s+` to one space, then reject `/[\p{Cc}\p{Cf}\p{Zl}\p{Zp}\p{Co}\p{Cn}]/u`; optionally reject a word mixing Latin and Cyrillic letters. Ukrainian ʼ (U+02BC) is `Lm` and stays legal. Do this before data exists.                                                                                                                                                                                                                                              |
| SEC-POS-03 | Low      | `server/services/position.ts:100-123` (no cap, no throttle); `server/repositories/position.ts:60` (`LIMIT 500` truncates silently); no DELETE by design (ADR-013); only search endpoints use `consumeRateLimit` (`server/security/rate-limit.ts:29`).                                          | A Head Recruiter (or a hijacked session) can create thousands of permanent rows. Past 500, pickers and the Admin all-verticals list silently drop alphabetically late names, and the UI cannot reach them to deactivate them. Fix: (a) per-vertical cap in `createPosition` (for example 300 rows, counted inside the transaction after locking the vertical row `FOR NO KEY UPDATE`, else 409 `POSITION_LIMIT_REACHED`); (b) a per-user write bucket via `consumeRateLimit(…, 'position:write:user', 30 per 60 s)` on create and PATCH; (c) the list returns an explicit `truncated` flag, or the repository fetches 501 and the service fails loudly rather than truncating.                                                                                                                                                                                     |
| SEC-POS-04 | Low      | `server/services/position.ts:131-140`, `:104-108`; `server/authz/can.ts:253`.                                                                                                                                                                                                                  | Order is `position.read` gate, then body parse (400), then scope (404), then manage (403). A REC/TL/HR sending a malformed body gets 400 instead of 403, so the write permission is checked after input parsing. It leaks nothing (schema is public, and existence is never involved), but it departs from permission-before-input. Fix when convenient: in both services call `hasAnyGrant(ctx.auth, 'position.manage')` and throw 403 before `parse`. Do not move any 404 decision before the scope check.                                                                                                                                                                                                                                                                                                                                                       |
| SEC-POS-05 | Info     | `server/repositories/position.ts:76-88` (lock uses the read scope and no `is_active` filter) vs list `activeOnly` for readers.                                                                                                                                                                 | Pickers hide inactive rows from read-only roles, yet `PATCH /positions/{id}` for an inactive id in their vertical answers 403 (vs 404 for unknown). It confirms existence of an inactive position only to someone who already holds the 122-bit id, and ids are visible on existing vacancies. Accepted. If the visibility model should be uniform, add `(is_active OR <manage scope>)` to the lock predicate for non-managers.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| SEC-POS-06 | Info     | `server/repositories/position.ts:21-27`: the count subquery ignores the caller's vacancy scope.                                                                                                                                                                                                | Safe today because `position.manage` is held only by Admin (G) and Head Recruiter (V), who also hold `vacancy.read` over the same verticals (`roles.ts:32-50`). It becomes a leak if custom roles (ROLE-04) can hold `position.manage` without `vacancy.read`; no such validation exists yet. Add a unit invariant now (every grant of `position.manage` is matched by `vacancy.read` of equal or wider scope, for built-in and custom roles) and enforce it in the ROLE-04 role editor.                                                                                                                                                                                                                                                                                                                                                                           |
| SEC-POS-07 | Info     | `server/services/position.ts:105,132` call `schema.parse` on input the route already parsed.                                                                                                                                                                                                   | A direct caller with unvalidated input (future Telegram or seed code) would raise a `ZodError`, which `mapError` does not map, giving a 500. Not reachable through `/api/v1`. Use `ValidationError` conversion if services gain non-route callers.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| SEC-POS-08 | Info     | `server/db/migrations/0012_position_catalog_writes.sql:4`.                                                                                                                                                                                                                                     | `GRANT INSERT` is table-wide, so a buggy writer could insert `is_active=false` or a chosen `version`. Optional hardening: `GRANT INSERT (vertical_id, name, created_by, created_at, updated_at)`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |

## Checks that held (evidence)

| Area                         | Result                                                                                                                                                                                                                                                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Finance                      | No `position.*` grant (`roles.ts:236+`); `define-route.ts:185` runs `requirePermission` before params, query and body parsing, so every route answers 404 for any input. Newman covers list, create (`body: {}`) and PATCH.                                                                                     |
| Admin aal1                   | Global grants are withheld without aal2 (`context.ts:47,82`), so `requirePermission` returns 401 `MFA_REQUIRED` (`can.ts:258`) on all three routes. An Admin who also holds a vertical role at aal1 keeps only that vertical scope, which is correct.                                                           |
| Horizontal IDOR (A to B)     | Create: `can(position.read, B)` is false, so 404, identical to an unknown vertical (`position.ts:107`, `verticalExists`). PATCH: the locked select is filtered by `positionScope`, so 404 identical to an unknown id (`:134-139`). List with `verticalId=B` yields an empty list, never 404 or 403.             |
| 403 vs 404 oracle            | 403 appears only after a successful read-scoped fetch, so it reveals only objects the caller can already read. `status=all` 403 reveals only the caller's own role. STALE_STATE (409) is reachable only after the manage check. No cross-vertical existence leak (see SEC-POS-05 for the narrow inactive case). |
| Vertical writes, mixed roles | `HEAD_RECRUITER@A + RECRUITER@B`: read `{A,B}`, manage `{A}` (grants merge per scope, `context.ts:88-98`); manage in B gives 403, `status=all` lists A only (covered by `positions.test.ts:360-392`).                                                                                                           |
| Mass assignment              | `createPositionSchema` and `patchPositionSchema` are `.strict()`; PATCH has no `verticalId`; `updatePosition` builds `changes` from explicit fields; `vertical_id` and `created_by` have no UPDATE grant (`0012:5`), asserted at `database.test.ts:721-773`; `created_by` comes from `ctx.auth`.                |
| CSRF                         | Origin equality, `application/json`, `X-CSRF-Protection: 1` and `Sec-Fetch-Site != cross-site` are enforced in `middleware.ts` and again in `define-route.ts:180`; routes are `force-dynamic`, responses `private, no-store`.                                                                                   |
| Lost update and races        | Row lock `FOR NO KEY UPDATE`, then version compare, then update, in one transaction; the unique index arbitrates names, loser rolls back with no audit or event (23505 maps to `POSITION_NAME_TAKEN`, `map-error.ts:21`). Tests cover 5 parallel creates and 2 same-version PATCHes.                            |
| Counts                       | `openVacanciesCount` is computed only for `status=all` under the `position.manage` scope, filtered by `vertical_id` and `deleted_at`; readers get `null`. Holds for current roles (see SEC-POS-06).                                                                                                             |
| Response DTO                 | Returns id, verticalId, name, isActive, version, createdAt, count only; no `created_by` or actor leakage.                                                                                                                                                                                                       |
| Audit and events             | Written in the same transaction; no-op writes nothing; audit `after`/`before` carry name, flag, verticalId only; event payloads are `{}` (`events/index.ts` strict schemas); no PII; Head Recruiter writes carry the correct actor.                                                                             |
| Audit viewer widening        | `audit.read` stays Admin-global and aal2 (`services/audit.ts:72,109,140,166`); position names are visible only to Admin. Labels render as React text and pass as ICU arguments (`audit-labels.ts:41-44`), so no HTML or format-string injection. Entity join is UUID-guarded (`audit.ts:41`).                   |
| DB grants                    | App role gets INSERT and UPDATE on `(name, is_active, version, updated_at)` only; no DELETE; RLS stays enabled (`app_rw` is BYPASSRLS like the other tables); default privileges revoke PUBLIC; FK `(position_id, vertical_id)` pins vacancies to the same vertical.                                            |
| Logging                      | Route log entry holds operation id, status, timing and user id only; unexpected unique violations still go to the 500 path with SQLSTATE and constraint name only.                                                                                                                                              |

## Follow-ups for T3 (UI)

- `/vacancies/positions` must `notFound()` for users without `position.manage` and redirect on `MFA_REQUIRED`, using the same gates as the API (no client-side-only hiding).
- Render names as text only; show the exact stored (normalised) name in the duplicate-conflict message so a look-alike is visible to the manager.
- Query key `['positions', filters]` must include `status` and `verticalId`; clear it on logout and role change so cached manager data does not outlive the session.
