## Engineer decision: last recruiter removed from an OPEN vacancy, the removed Recruiter sees it and can reclaim (D130-2)

**Accepted, no vulnerability (Info / owner awareness).** Reasons:

- The `UNASSIGNED_OPEN` scope is vertical-wide and independent of history. Any Recruiter of the vertical, the removed one included, could have claimed this vacancy before it was first assigned. Removal restores the vacancy to exactly that pool state; it never granted a right the user lacked.
- The Recruiter still cannot remove anyone, self included (test 734), and a reclaim is a normal audited claim (`method: SELF`, one audit row, version +1).
- The Head Recruiter keeps control: assign another recruiter in the same minute and the pool closes; `ON_HOLD` hides it from the pool (D130-5).
- The pre-review row 2.19 said "removed recruiter then GET = 404". That holds when colleagues remain or the vacancy is `ON_HOLD`, not for the last recruiter on `OPEN`. Correct the ADR sentence; the test at line 667 and 683 already pins both cases.
- If the owner wants a Head to exclude a specific recruiter, that needs a new concept (per-vacancy block list). Not a Phase 2 item. Add one line to ADR-017 Consequences, and mention it to the owner with the A5 claim-cap question (same family: first-claim-wins fairness).
