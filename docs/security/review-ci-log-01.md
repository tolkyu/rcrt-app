## Implementation decisions

- Automatic Git commit/diff capture is explicitly disabled in the main and perf configs; lighthouse inherits the perf setting. Only that capture option changed in the perf config. Before **both** reporter sinks receive configuration, `privateReportConfig` creates a separate top-level/project metadata projection: static `diagnosticPolicy: CI-LOG-01` and, at top level, only a positive safe-integer actual worker count bounded by the configured worker count. Arbitrary user metadata, CI metadata, Git author/commit data, Git diffs and user `shuffleSeed` text are omitted without altering the runtime configuration objects.
- Recognizable credential-bearing test tags are sanitized before either sink renders them. Playwright 1.64.1 exposes tags through a getter without a setter; the adapter shadows it with a configurable sanitized presentation value rather than assigning to the getter. Ordinary tags and project/test labels remain available; the version pin remains unchanged.
- `tests/support/safe-network-error.ts` retains an approved network code and static operation label without raw headers, URL/query/body, message or cause. Both fetch/response-transform paths in `tests/e2e/screens.ts` use it. Document/RSC teardown classification retains the exact original `String(error)` predicate; the masked API path gains no teardown suppression. No fetch retries were added or broadened.
- `tests/support/private-reporter.ts` implements the public reporter callbacks and delegates to the list/HTML implementations exported by `playwright/lib/runner`. These exports and their v2 `onConfigure(config)` / `onBegin(suite)` contract were inspected in the installed package. This is a **pinned internal adapter**, not a stable public delegation API: the constructor rejects versions other than `1.64.1`. The canary validates real serialization and the CLI reporter override used by the perf commands.
- `tests/support/report-privacy.ts` removes entire credential-bearing diagnostics rather than trying to recognize JWT formats or redact just one header value. It sanitizes error message/stack/value/cause, global errors, nested recorded step errors/titles/subtitles and annotations, and removes recorded request parameters. It revisits all results before HTML serialization. Ordinary assertion text and file/line locations remain available.
- Worker stdout/stderr are untrusted, including fragmented or bare token writes: the adapter forwards only a fixed omission notice. Source snippets and **all raw attachments** are omitted from the report. The sole attachment exception is a fresh, bounded, reconstructed `sanitized-page-context` body described below; no raw error-context text or file path is forwarded. Traces, storage state, generic text/JSON, accessibility JSON and screenshots remain excluded. Safe test names, statuses, retry outcomes, step hierarchy, source locations and network codes remain visible; the reporter never overrides run status.
- `playwright.config.ts` selects only the private adapter and disables tracing in CI. Local `retain-on-failure` traces still exist in the raw output directory and must be treated as sensitive. Screen capture code and its local/committed PNGs are unchanged.
- `.github/workflows/ci.yml` runs the synthetic canary, retains the same build/size/runtime/lighthouse sequence with the private reporter and traces off for both perf browser commands, and uploads only `playwright-report/`. The always-upload step cannot reach `.cache`, raw `test-results/`, perf results, or screenshot directories through its configured paths. Timeout remains 80 minutes; all serial vacancy projects and `OPEN_LIST_SPECS` remain unchanged.

## Trace/artifact decision for owner review

No generic trace redaction is claimed. Traces can contain network bodies, cookies, request metadata and captured state beyond header strings; proving safe rewriting of every ZIP/resource format is outside this bounded patch. The chosen fallback disables CI traces and excludes raw artifacts from publication instead of uploading a partially scrubbed trace.

The cost is reduced hosted debugging detail: raw worker logs, source snippets, raw attachments and standalone perf JSON/screenshots are absent from uploaded artifacts. The approved follow-up retains only reconstructed structural context with exact known static UI copy. Local raw diagnostics remain available to a trusted developer, and existing screenshot galleries are still generated. Restoring any other artifact category requires a separately verified publication policy; merely removing a header string or re-adding a raw directory is insufficient.

The text filter covers recognizable credential-bearing diagnostics and the real Playwright call-log forms exercised below; it is not a universal detector of arbitrary unlabeled secrets embedded in otherwise benign strings. Alternate reporters, extra `PW_TEST_REPORTER` sinks, debug transport output, app/web-server output before/outside reporter initialization, and historical logs are outside this adapter's guarantee. CI must retain the configured reporter and upload allowlist. Do not publish local raw output.

### Reconstruction and file policy

- `tests/support/safe-page-context.ts` accepts only the pinned producer envelope and a small sequence/role/state grammar, without a general YAML evaluator. It reconstructs a new text tree. Instructions, test identity/location, error text, source frames, raw YAML and source file paths are never copied.
- Roles and state tokens come from explicit allowlists; heading level is bounded to 1–6. Reference IDs and cursor metadata are discarded. Labels/text survive only as an **exact** match to a trusted static Cyrillic leaf of `messages/uk.json`, using the trusted leaf value for output. ICU/interpolation templates, control characters, rich markup and URL/email-like leaves are excluded. There is no secret-keyword filter in this reconstruction path. Unknown names/text become `[omitted]`; URLs/placeholders are discarded; input values and descendant text are omitted even if they equal a known UI string.
- Limits: 256 KiB entire producer file, 5,000 remaining envelope lines, four snapshots/eight error blocks, 64 KiB and 512 lines per snapshot, depth 16, 4,096 characters per snapshot line/path, and 64 KiB reconstructed output. Unsupported roles, attributes, scalar variants, malformed fences/sections, invalid UTF-8 and over-budget input omit the context entirely.
- Only failed/timed-out results with errors may supply raw candidates named `error-context`, typed exactly `text/markdown`, with no body and an absolute canonical path whose basename is exactly `error-context.md`. The file must be under a configured project output root, with no symlink/junction in its path; hardlinks, non-files and path escapes are rejected. A no-follow descriptor where supported, device/inode/size checks, repeated path checks and one bounded read avoid generic path-based attachment pass-through.
- The actual pinned canary delivers two metadata-identical references to the same producer file per result. One or two identical references are collapsed to one read; distinct paths, inconsistent types/bodies, or more candidates fail closed. The envelope/path checks establish a narrow accepted format, not cryptographic provenance from arbitrary trusted test code; even a matching forged envelope can output only the same allowlisted static content.
- A per-result weak cache stores only reconstructed immutable text, including cached rejection. `privateResult` and final suite re-sanitization create a fresh fixed-name `sanitized-page-context` buffer without re-reading the raw source or trusting a previously supplied attachment. Step attachments remain empty. Every other result attachment remains excluded, including a user-supplied attachment with the safe name.

The reconstruction intentionally loses dynamic copy, interpolated text, concatenated labels that do not exactly match one static leaf, unsupported/large trees and all non-structural data. An exact match establishes public-copy membership, not how the DOM obtained that text. The unchanged broader error/report filter is still not a universal detector of arbitrary unlabeled secrets; this follow-up does not expand its guarantee or claim binary trace redaction. No raw attachment staging directory was added to CI uploads.
