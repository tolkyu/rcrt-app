## Accepted and later-phase boundaries

- **D68:** delivery-dependent magic-link latency/error eligibility signal is explicitly accepted by the owner. No timing equalisation or deferred delivery was introduced.
- **SEC-EML-01 / T-A14:** orphan Auth identity reconciliation is an existing non-blocking privacy follow-up for Phase 6 jobs; no application link means no app access. No new cron or identity deletion is introduced here.
- **SEC-CORE-14:** a local database marker is optional defence against an empty hosted database reached through a loopback tunnel. Existing loopback, endpoint/role matching and non-demo identity refusal stay intact; this review does not claim a new marker.
- **SEC-CORE-16 / D53:** routed-vacancy read scope remains a gate before routing ships, with Phase 2–3 tables; current code fails closed.
- **Hosted release:** before real data, verify A04/B06/C06/D03/H04/I03/R03 against the actual project: asymmetric keys/legacy-key policy, token/refresh settings, exact production redirects, provider signup/linking flags, no demo/password identities, built-in limits and factor cap. Local tests cannot substitute for this evidence. DG-03, CI/advisory gates and drift-check tooling are coordinated separately with DevOps.

Tooling policy review: `scripts/check-audit.ts` rejects every production advisory and unrecognised high/critical development advisory. Accepted tooling entries require exact GHSA/module/severity and scoped dependency paths. The committed-only OpenAPI converter has the same trusted-input, undeployed boundary as accepted Newman tooling (T-S06); no blanket suppression or forced Newman overrides are accepted.
