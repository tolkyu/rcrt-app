## Verified controls

| Area                          | Evidence and result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Current authorization         | `components/vacancies/use-edit-vacancy-content.ts:41` consumes the single passed ACCESS result, adding no observer or role policy. Saved baseline is separate from current readable status/capability. Entry requires matching readable content; save also requires current eligible access, both runtimes ready and no stale/closed/fresh-read gate. Server PATCH remains the write authority.                                                                                                                        |
| Invalid and NULL semantics    | `lib/vacancy-content-form.ts:8` represents unchanged, whole valid/invalid replacement, and explicit Clear with its exact prior buffer. Invalid replacement remains dirty and blocks the entire body; no previous-valid fallback. Clear serializes NULL, unchanged fields are omitted and deliberate empty documents remain documents. Undo restores the original buffer, including invalid input/issues. No logging/persistence added.                                                                                 |
| Strict request boundary       | `lib/vacancy-content-submit.ts:24` builds only changed document keys with the saved baseline version, then validates the shared strict schema. The lazy-loaded submission module validates again before fetch and validates the shorter PATCH response. Unsafe valid-tagged content, overposting and empty bodies cannot bypass schema enforcement. Failure state retains translated field codes/paths rather than raw input.                                                                                          |
| Synchronous dispatch gates    | `use-edit-vacancy-content.ts:99` updates the latest form ref synchronously. Submit rechecks that snapshot's ID, invalid/readiness/stale/closed/freshness gates before taking the ref lock and awaiting ACCESS. Same-event invalid updates and pre-stale callbacks cannot serialize an older valid buffer. Field/Clear/undo changes freeze immediately while locked.                                                                                                                                                    |
| Baseline adoption / caches    | `use-edit-vacancy-content.ts:108` adopts canonical PATCH documents/version only into local clean baseline, never GET status/eligibility or GET cache. Saved Clear forces the affected runtime reset/readiness cycle to discard retained undo input. Prefix invalidation and a fresh ACCESS read are required before another save; old/failed reads cannot satisfy the saved revision barrier.                                                                                                                          |
| Recoverable and denied states | Same-ID 500/checking preserves local invalid/Clear-undo buffers and leave protection, with saving blocked. New revision or stale response retains edits and requires explicit successful reload. Closed state blocks writes. PATCH 403 refreshes read access and independent grants without silently rebasing edits; terminal 401/GET 404 hides/discards baseline and buffers and releases leave protection. Ambiguous responses do not infer success from version alone.                                              |
| Late result isolation         | `use-edit-vacancy-content.ts:139` checks mounted ID/client lifetime and ACCESS token around asynchronous dispatch/adoption. Old ID/client/unmount/denial results cannot adopt documents into the current state. `lib/vacancy-content-submit.ts:76` handles confirmed retired success only by invalidating the captured original client/ID prefix and list prefix with `refetchType:'none'`; it inserts no data and starts no reads.                                                                                    |
| F10 history / readiness       | `components/rich-text/rich-text-editor-runtime.tsx:115` reports not-ready on changed resetKey, normalizes/compares the target, then recreates EditorState with current schema/document/selection/stored marks/plugins. This reinitializes UndoRedo history even for equal-content explicit adoption, preventing old discarded/Clear buffers from reappearing through undo. It retains the Editor instance and reports readiness from validation of live JSON. Unchanged resetKey preserves ordinary history/selection. |
| F10 keyboard delta            | Runtime reserves Shift+Enter for hard breaks and leaves only noncomposing Mod+Enter to the guarded parent handler. Existing schema/paste/URL and dialog containment boundaries remain unchanged. Official UndoRedo comes from pinned `@tiptap/extensions` 3.34.0; it adds no document schema or storage policy.                                                                                                                                                                                                        |
