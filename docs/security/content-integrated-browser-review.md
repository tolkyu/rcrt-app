## Focused fix verification — terminal navigation

- Browser evidence supplied by the orchestrator: after PATCH 401, documents disappeared but the page remained on its terminal skeleton; the refresh RSC contained `NEXT_REDIRECT`. Dirty form teardown called `history.back()` (`components/ui/use-leave-guard.ts:101-119`), whose popstate could discard the pending Next refresh. This was a navigation defect despite successful content cleanup.
- Verified the bounded fix at `components/vacancies/vacancy-content-edit-form.tsx:65-70,133`: ContentEditor passes the existing guard ref and captures its release handle in a layout effect. Layout teardown disarms the guard before its passive cleanup can pop history (`components/ui/use-leave-guard.ts:135`). No permission, cache, document-retention or shared guard API change was introduced. Terminal rendering still removes the editor tree (`vacancy-content-edit-form.tsx:247`).
- Inspected the focused regressions (`tests/unit/vacancies/content-edit-form.test.ts:400`): terminal 401/403/404 removes editors, Clear undo, dialogs and cached content without calling history.back; 401 also requests refresh. The positive Cancel case (`:333`) still requires Stay/Confirm and performs no write. Orchestrator execution evidence: all three terminal regressions failed before the fix with one back call; the fixed form file passed **28/28**.
- Focused security source verification: **PASS**. No test/build/browser run repeated by this reviewer. Fresh-build browser confirmation of the redirect remains pending; the independent code reviewer is separately checking the same minimal fix. This is blocking-fix verification under D126, not a second general review.
