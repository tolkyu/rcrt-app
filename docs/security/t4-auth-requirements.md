# T4 (authentication) — security requirements checklist

- Owner: security-engineer · Date: 2026-10-31 · Status: binding for T4. Each item needs its test before T4 counts as done.
- Sources: PRD SEC + ROLE-05/06 + D22 (second TOTP + Admin reset, no recovery codes), D23, D33, D42, D44, D45, D63. Threat model T-A01…T-A13, DG-01/02/05/07/08/09/12b/15/16. ADR-002 §4/§10/§11, ADR-010.
- Status words: **DONE** (verified in the uncommitted Codex slice, needs a commit), **OPEN** (must build), **FIX** (finding in the existing slice).
- Test IDs map to `docs/test-plan.md` SEC-TC-xx where one exists. Tests use a fixed clock, real ES256 keys and a local Supabase where stated.

> This checklist preserves the initial review snapshot; OPEN/FIX labels below are not a current implementation inventory. Current corrections and evidence: `review-phase-1-auth-completion.md`. Owner decision D68 supersedes SEC-T4-02/T4-C03: eligible delivery failures are visible (503), and delivery completes before success. Unknown/inactive/pending addresses remain neutral; equal latency is not promised. SEC-T4-08 now uses only Vercel's trusted header in deployed preview/production; an unknown IP uses one conservative HMAC bucket, with null retained in audit. Mail delivery is composed server-side with a token-hash fragment; a GoTrue default template is not used by the app flow.
