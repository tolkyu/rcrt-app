# Security review — Phase 2 vacancies V1 (scoped read + open-work guard)

Date: 2026-11-08. Scope: ADR-012, VAC-01..04/07, VIS-01..03, ROLE-06, D1/D24/D43/D53/D67, UI-09. Reviewed the uncommitted working tree on `phase-2`: vacancy scope adapter, repositories, service, `/api/v1/vacancies` routes, `(app)/vacancies` layouts and pages, migration 0011, demo seed, deactivation and role-removal guard. No code was changed. QA was running tests concurrently, so this review is static plus one ad-hoc SQL-rendering check (SEC-VAC-01); the suites were not run here.

**Verdict: approved with one Medium fix required before commit (SEC-VAC-01).** No Critical or High findings. Scoping, 404 uniformity, Finance and MFA behaviour, the migration grants and the guard ordering all hold. The remaining items are Low or Info.

## Residual notes

- D53 (owning recruiter reads a routed vacancy) stays closed. Before the first application or routing feature, add a dedicated scope kind with SQL and in-memory parity and allowed and denied tests, as ADR-012 already states.
- Test gaps to add with the fixes: literal `%`, `_`, `\` search (SEC-VAC-01); NUL in `q` (SEC-VAC-02); a page-level test that a pure Admin at aal1 is redirected to MFA, not 404; a per-role salary DTO snapshot (SEC-VAC-05).
- The threat model has no vacancy-read row yet. Suggested addition to `threat-model.md` §3.2: "vacancy list/detail scope, anchor cursor, public-number gaps (SEC-VAC-07), search escape (SEC-VAC-01)".
- Items 1 to 3 below should be closed before commit; the rest can follow.
