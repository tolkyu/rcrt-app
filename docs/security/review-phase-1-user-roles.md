## Verified controls

| Control                                  | Evidence / result                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Admin with verified MFA only             | Service checks `settings.users.manage` before target lookup or role validation (`user-roles.ts:48`). The centralized permission requires global scope and MFA (`server/authz/permissions.ts:130`). HEAD_RECRUITER/FINANCE denial and aal1 Admin `MFA_REQUIRED` are integration-tested.                                                                                                                                |
| Strict, bounded role input               | `updateUserRolesSchema` is strict, requires a positive version and bounds roles to 50 (`lib/schemas/user.ts`, `lib/schemas/auth.ts`). Shared `roleSetIsValid` rejects unknown roles, duplicates, nonexistent verticals, scoped roles without a vertical and global ADMIN/FINANCE with a vertical (`server/services/auth/invite.ts:68-83`). Empty replacement is explicitly allowed; empty invitations remain invalid. |
| Self / last active Admin (D45)           | Own ADMIN removal returns `SELF_ADMIN_REMOVAL` (`user-roles.ts:70-75`). Removal of another ADMIN takes `pg_advisory_xact_lock` and rechecks another accepted, active holder; pending invitees and deactivated holders do not count. The advisory lock covers distinct target rows, preventing two last Admins from both removing the other. UI hints are advisory; the service independently enforces the invariant.  |
| Concurrent editors (ADR-006)             | Target user is locked with `FOR NO KEY UPDATE`; the version is compared before changes and incremented in the same transaction (`user-roles.ts:57-62,79`). Exactly one request with a shared initial version succeeds; the loser returns `STALE_STATE`. NO KEY UPDATE remains compatible with foreign-key key-share locks, preventing cross-admin actor/created-by deadlocks.                                         |
| Invite acceptance races                  | Edit locks pending invite → user → current roles, matching acceptance. Acceptance reads the current role table, never restores the invitation's old role snapshot. Role removal to an empty set invalidates acceptance until roles are assigned again. Tests cover separate-connection acceptance/edit races and stale versions.                                                                                      |
| Immediate access changes / mandatory 2FA | `findPrincipal` reads roles from `user_role` on every request (`server/repositories/principal.ts:90-96`); request auth is rebuilt through `loadAuthContext`. Integration coverage confirms lost and added grants on the target's next request and withholds FINANCE global grants until aal2. In-flight requests retain their already-loaded context, consistent with the next-request contract.                      |
| State guards                             | A missing user returns 404, a deactivated user returns `USER_DEACTIVATED`, an unchanged set returns `ROLES_UNCHANGED`, and failures leave version/assignments/events unchanged. D43 open-work reassignment is explicitly deferred to Phase 2–3 in STORY-ROLE-01-2 and wireframe §1.4 because work tables do not exist yet.                                                                                            |
| Atomic history and audit                 | Role deletion/insertion, version increment, one allowlisted `user.role_removed`/`user.role_assigned` event per difference and one `user.roles_changed` audit row commit together (`user-roles.ts:77-105`). Payloads contain role codes/vertical IDs only. Audit retains the exact before/after sets; no token, address or free text is logged.                                                                        |
| Transport protection                     | Shared API factory verifies trusted Origin + CSRF header, limits JSON body bytes, validates response shape and sends `Cache-Control: private, no-store`. The endpoint inherits these controls; no alternate mutation channel is added.                                                                                                                                                                                |

Verdict: **APPROVED** for this bounded slice, subject to green coordinated automated checks. SEC-ROL-01 remains in T9; SEC-ROL-02 is mandatory follow-up for the next deactivation slice. Phase 1 is not complete.
