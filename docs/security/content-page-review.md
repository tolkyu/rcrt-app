- Final integrated approval waits for CARD, UX, performance and CI gates. Threat model unchanged.

## F1 verification

- **F1 resolved.** `use-vacancy-content-access.ts:106-114` maps GET 403 to terminal `notFound`; the only callers are `:135` (`query.error` of the GET observer) and `:193` (`refetch` result), so the change cannot touch a PATCH error.
- PATCH 403 path unchanged: `handleWriteError` (`:221-232`) denies only on 401 and otherwise calls `revalidate`, so a readable-retained 403 still ends in a successful GET with the form kept disabled. Only a following GET 403/404 evicts.
- No existence leak: reason `notFound` renders the same `ContentUnavailable` screen as 404, with the same copy. Side effect (accepted): a mixed-role user whose grants are withheld pending MFA also sees it on a GET 403. Tests attributed to the engineer; not rerun.
