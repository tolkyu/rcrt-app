## Trusted proxy contract

Vercel documents that it overwrites client-IP headers to prevent spoofing and provides `x-vercel-forwarded-for` independently of external X-Forwarded-For rewriting. The application uses only that header after a server environment gate. Neither a request's `x-vercel-id` nor a forwarded header can enable the gate. Local/vercel-development and other hosting environments report no trusted IP until a separate proxy boundary is explicitly implemented. [Vercel request headers](https://vercel.com/docs/headers/request-headers), [system environment variables](https://vercel.com/docs/environment-variables/system-environment-variables).

Malformed, missing or comma-separated provider IP values return null. Audits therefore record an unknown IP rather than a caller-chosen address. Null should map to one fixed limiter identifier, never to a made-up audit address.

## Reviewed controls and limits

- Public authentication factories require POST plus configured Origin, JSON and CSRF header. Authenticated factories now resolve context before parsing input; existing protected API factories are separate.
- Session context checks the Supabase session for the same user, app session state, activation, absolute/idle policy and MFA lock. Background requests do not touch idle activity; session expiry revokes provider and app sessions.
- Confirm/invite establishment verifies returned JWT and current principal, records the session/login, and commits cookies afterward. Failure paths clear staged credentials. Invite hashes, conditional single-use consumption and scoped role validation exist; live provider behavior/concurrency still needs fresh QA.
- Cookies are currently HttpOnly/SameSite=Lax, Secure for HTTPS, with absolute-lifetime caps. No current browser Supabase client needs token access; this differs from the earlier Realtime-oriented cookie design.
- Owner now requires an explicit delivery failure for eligible active users, implemented as the sanitized delivery-failure response. Unknown/ineligible responses remain neutral. This deliberately permits an eligibility signal during provider failure and an eligibility-dependent delivery wait; the review records this product exception and does not replace it with the old neutral/deferred-delivery behavior.
- Existing security requirements contain OPEN/FIX labels from older snapshots. Source presence alone does not close full T4; real disposable-provider flows, session expiry/refresh revocation, MFA failure/recovery, invitation races and production configuration remain completion gates.
