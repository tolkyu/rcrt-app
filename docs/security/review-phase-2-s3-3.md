| F1  | Low  | `edit/loading.tsx` builds its heading from any readable vacancy and never calls `vacancyAuthorKind`, unlike the layout and page. For HR/TL/Head HR on a vacancy they may read, the data is within their read scope and the final response is HTTP 404 with the not-found tree (E2E asserts 404 plus the not-found UI), so nothing outside scope is exposed. There is no test that the 404 HTML lacks the vacancy title/number. | Optional: add an E2E assertion that the 404 body for HR on `/edit` does not contain the vacancy number or title.                                                      |
| F3  | Info | The form receives the full `VacancyDetail` as an RSC prop, including `teamLead` and `probationDays`, also when the role has no grant for those fields (they are hidden in the UI). The data belongs to the caller's own draft and the same data is returned by `GET /vacancies/{id}`, so this is not an escalation.                                                                                                                                                  | Accept. ## Residual notes (no action for this slice)

- Gap (4)/(8) in PROGRESS: the loading skeleton's `x-pathname` path has no browser test. Given F1 and the header being middleware-controlled, no security risk; a test that a non-author never sees the skeleton heading would close it together with F2.
