# Security review — Phase 2 vacancies V2b S2 (author-only draft lifecycle)

Date: 2026-11-10. Scope: uncommitted `phase-2` diff — `PATCH/DELETE /api/v1/vacancies/{id}`, `POST .../publish`, `POST .../cancel`, `server/services/vacancy-draft.ts`, the shared helpers extracted into `server/services/vacancy.ts` (`lockAuthors`, `authorizeAuthoring`, `consumeVacancyWriteLimit`), `server/repositories/vacancy.ts` (`lockVacancy`, `updateVacancy`), `server/authz/{can,types,vacancy-scope}.ts`, `server/events/index.ts`, migration `0015_vacancy_draft_lifecycle.sql`, `lib/schemas/vacancy.ts` (`patchVacancySchema`, `cancelVacancySchema`), ADR-012 addendum. Static review plus `vitest run tests/unit/authz/vacancy-author.test.ts tests/unit/vacancy-draft-schema.test.ts` (50 passed). Integration tests need Docker and were not run.

**Verdict: approved. No Critical or High.** Draft privacy, 404/403 uniformity, lock order, stale-version handling, re-validation at publish, idempotency and column grants all hold. One Medium (latent, no reader exists yet) must be fixed before any vacancy timeline reader ships; four Low hardening items and several Info notes.

| SEC-V2S2-01 | Medium   | `server/authz/vacancy-scope.ts:86-93` (`vacancyEventReadWhere`: `opened_at is not null OR (created_by = me AND authoredIn)`); ADR-012 addendum «Events» says «to everyone in scope once the vacancy opened»; the module is declared the only one allowed to read events.                                   | The predicate implements only the draft rule. For any opened vacancy it is true for every caller, with no vertical, Team Lead or assigned-recruiter scope. The first timeline reader that trusts it («the only module that may read vacancy events») would leak every opened vacancy's events across verticals and recruiters (vertical or horizontal IDOR). Fix: build it on the one read predicate, `exists (select 1 from vacancy where vacancy.id = entity_event.vacancy_id and ${vacancyReadWhere(ctx)})`. That keeps the draft and cancelled-draft arms and adds the role scope. Do not add a `deleted_at` filter (the author must still see a deleted draft's events, test at `vacancies-draft-lifecycle.test.ts:1053`). Keep the outer `vacancy_id is null` arm. Add integration cases for an opened vacancy: same-vertical Recruiter not assigned, other-vertical Recruiter, other-vertical Head Recruiter, Team Lead of another vacancy. Check the rendered SQL with an explicit table alias, because Drizzle drops qualifiers in single-table selects (see `repositories/position.ts` note) and `vertical_id` exists on both `entity_event` and `vacancy`. Today it binds correctly only because the inner scope shadows the outer one. |
| SEC-V2S2-02 | Low      | `tests/unit/authz/vacancy-author.test.ts:290-291` (`EVENT_TABLE` matches only the Drizzle import or `schema.entityEvent`).                                                                                                                                                                                 | The architecture guard misses a reader written as raw SQL (`db.execute(sql\`select ... from app.entity_event\`)`, a SQL view, a stats job). Fix: also match `/entity_event\b/`(and`change_feed`) over `server/`, `app/`, `lib/`and`components/`excluding`server/db/migrations`, then list the allowed modules. `server/repositories/user.ts`stays allowed (types`user.%`and`vertical.tl_priority_changed` only, asserted by the second test).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| SEC-V2S2-03 | Low      | `server/db/migrations/0015_vacancy_draft_lifecycle.sql:3` (UPDATE on `status`, `opened_at`, `closed_at`, `cancelled_at`, `deleted_at/by`, `delete_reason`, `version`); `server/repositories/vacancy.ts:226-236` (`updateVacancy` filters on `id` only).                                                    | The grant is as narrow as column-level allows (no `created_by`, `vertical_id`, `source`, `public_no`, `created_at`, no DELETE), but the privacy invariant `CANCELLED AND opened_at IS NULL` = «author-only» rests on `opened_at` never being cleared, and nothing below the service enforces it. A later bug (VAC-08 close/cancel of an opened vacancy, restore) that nulls `opened_at` or flips an OPEN row to DRAFT would silently hide a live vacancy from everyone but its author. Fix: precedent `guard_vacancy_public_no` (0011:111). Add a `BEFORE UPDATE` trigger in 0015 that raises when `OLD.opened_at IS NOT NULL AND NEW.opened_at IS DISTINCT FROM OLD.opened_at`, when `OLD.status <> 'DRAFT' AND NEW.status = 'DRAFT'`, and when `OLD.status = 'CANCELLED' AND NEW.status <> 'CANCELLED'`; add a `database.test.ts` case. Also give `updateVacancy` an `expectedStatus` argument (`WHERE id = $1 AND status = $2`) and fail when no row changes, so a lifecycle write never relies on the lock alone.                                                                                                                                                                                                                              |
| SEC-V2S2-04 | Low      | `server/services/vacancy-draft.ts:262-343` (publish takes no version; `STALE_STATE` at `:304` compares only Team Lead and position); `requestHash({ vacancyId })` at `:277`.                                                                                                                               | Publish opens whatever is stored now. The author's second tab or a retried older client can publish content the author did not last see (PATCH is protected by `expectedVersion`, publish is not). Only the author is affected, so Low. Fix: add a required `expectedVersion` to the publish body (or `If-Match`), compare it with `row.version` on the locked row (409 `STALE_STATE`), and include it in the idempotency `requestHash`. Update OpenAPI and the Newman case.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| SEC-V2S2-05 | Low      | `server/services/vacancy-draft.ts:82-91` (`lockDraft` refuses any non-DRAFT, so a cancelled draft cannot be deleted); `server/repositories/vacancy.ts:179-194` (`countLiveDrafts` counts `DRAFT` only); `server/services/vacancy-draft.ts:376-391` (reason ≤ 500 chars free text into `entity_event_pii`). | Never-opened cancelled and soft-deleted drafts are invisible to Admin by design (D92), so nobody can ever clean them. They are not bounded (create 100/day then cancel frees the 50-draft slot), are not removable by their author, and carry free-text reasons that may name people. When the author is anonymised or purged these rows and their PII side rows are orphaned. This is a GDPR retention gap, not an access gap. Fix (needs an owner decision, route through `docs/OPEN_QUESTIONS.md`): (a) a purge-job rule that hard-deletes never-opened cancelled and deleted drafts, with their `entity_event` and `entity_event_pii` rows, N days after closing and on author anonymisation; (b) count cancelled drafts in a separate cap or allow the author to delete a cancelled draft; (c) assert in the user-purge task that `entity_event_pii` rows of events whose actor is purged are erased. Record it in the threat model.                                                                                                                                                                                                                                                                                                          |

## Checks that held (evidence)

| Area                                      | Result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Finance and unauthenticated               | `define-route.ts` runs CSRF, then `requirePermission('vacancy.read')` (Finance has none, so 404) and `requireGrant: vacancy.create` before params, headers and body are parsed (`define-route.ts:~172-178`); the service repeats both in `admit` (`vacancy-draft.ts:51-54`). Admin without aal2 gets 401 `MFA_REQUIRED`.                                                                                                                                                                                                                                                                        |
| 404 vs 403 uniformity                     | Foreign draft, another author's cancelled draft, deleted draft, lost-role draft and unknown id all go through `readVacancy` → `vacancyReadWhere` and give the same 404 (`vacancy-draft.ts:61-71`). The 403/409 split (`VACANCY_NOT_DRAFT`) appears only for a vacancy the caller can already read through GET. HR, Head HR and Team Lead get 403 before any object lookup, independent of the id. A replay with a key bound to another draft gives 409 regardless of whether that draft exists, so there is no oracle.                                                                          |
| Draft visibility                          | `vacancyReadWhere` (`vacancy-scope.ts:61-82`): draft arm and cancelled arm both require `created_by = me` and a current authoring role in the vertical; the role arm excludes `DRAFT` and `CANCELLED AND opened_at IS NULL`. The `NOT (status='CANCELLED' AND opened_at IS NULL)` expression has no NULL pitfall (`status` is NOT NULL, `IS NULL` yields boolean). Admin, Head Recruiter, Team Lead and HR cannot reach another author's draft by list, status filter, `q` search, `V-n` search or id. A role arm cannot be reused elsewhere: `vacancyScope` stays private (architecture test). |
| Other vacancy readers                     | `repositories/position.ts:21-27` counts `status = 'OPEN'` only; `vacancy-work.ts:24` uses `OPEN, ON_HOLD`; no other reader of `vacancy` exists. Drafts therefore never enter counts, position usage or user-deactivation checks.                                                                                                                                                                                                                                                                                                                                                                |
| Author authority                          | `authorOf` (`vacancy-draft.ts:94-103`) re-derives the caller's roles from fresh rows after `FOR SHARE` on the users; a lost role is 404, a lost Team Lead or probation grant is 403, a deactivated author is 403. `lockDraft` additionally requires `created_by = caller` on the locked row (`:82-91`). Admin and Head Recruiter have no extra reach.                                                                                                                                                                                                                                           |
| Privilege change between save and publish | Publish re-runs `authorizeAuthoring` on the stored `team_lead_id` and `probation_days` with the fresh roles, re-checks Team Lead eligibility (active, still Team Lead of that vertical), re-checks the position (active, same vertical, `FOR SHARE`). Tests at `vacancies-draft-lifecycle.test.ts:607-725, 1247-1325`.                                                                                                                                                                                                                                                                          |
| Lock order and TOCTOU                     | Idempotency row → users (`FOR SHARE`, id order, roles read in the next statement for READ COMMITTED) → position `FOR SHARE` → vacancy `FOR UPDATE`. Position PATCH takes only the position lock and user deactivation only user locks, so there is no cycle. State, owner, deletion and version are judged on the locked row (`lockDraft`, `vacancy-draft.ts:82-91`; version at `:145`). Two publishes, publish vs delete, edit vs publish and role removal vs publish are covered by races at `:1191-1340`.                                                                                    |
| Stale version                             | `expectedVersion` is required, strict, compared on the locked row; a no-op patch still checks it and writes nothing (no version bump, no event). `version` and `updated_at` change only in `updateVacancy`. (See SEC-V2S2-04 for publish.)                                                                                                                                                                                                                                                                                                                                                      |
| Mass assignment                           | `patchVacancySchema` is `.strict()` with no `verticalId`, `status`, `createdBy`, `number`; `VacancyChanges` omits `id`, `publicNo`, `verticalId`, `source`, `createdBy`, `createdAt`, `updatedAt`, `version`; the service builds the changes from explicit fields; salary, currency and min ≤ max are validated on the merged result, backed by `vacancy_salary_chk`. Rich text goes through the DG-13 allowlist schema (50 KB, https/mailto only) and is re-parsed idempotently by the service. Body capped at 1 MiB (`read-json.ts`).                                                         |
| Idempotency                               | Key scoped by user and operation `vacancy.publish`; hash binds the draft id; replay is checked before the draft state and re-read through the scope; a failed first attempt rolls back the claim; stores no response body or PII.                                                                                                                                                                                                                                                                                                                                                               |
| Rate limits                               | Shared `vacancy:write:user` bucket (30/min) is consumed after the permission gates and before parsing and id lookup, so 400/404/409 probes are counted. The daily create cap (100) is consumed at creation for both modes, so publish-from-draft cannot bypass it; live drafts capped at 50.                                                                                                                                                                                                                                                                                                    |
| CSRF                                      | PATCH, DELETE and POST publish/cancel are unsafe methods through `defineRoute`: Origin, JSON, `X-CSRF-Protection`, `Sec-Fetch-Site` checks in middleware and again in the route; `force-dynamic`, `private, no-store`.                                                                                                                                                                                                                                                                                                                                                                          |
| DB grants (0015)                          | Column-level `UPDATE` only; no DELETE; `created_by`, `vertical_id`, `source`, `public_no`, `created_at` immutable for `app_rw` (asserted in `database.test.ts`); public_no trigger intact; RLS stays enabled; partial index matches the cancelled-draft arm. See SEC-V2S2-03 for the remaining defence-in-depth gap.                                                                                                                                                                                                                                                                            |
| Events and PII                            | Draft-era events have `vertical_id = NULL` (no vertical feed catches them); payloads are strict schemas (field names, statuses, no values); the cancel reason only in `entity_event_pii`; no `change_feed` row is written; the user timeline reader selects `user.%` and `vertical.tl_priority_changed` only. Route logs carry operation id, status, timing and user id. Idempotency rows and the rate-limit key hold no personal data.                                                                                                                                                         |
| Audit                                     | Publish writes exactly one `vacancy.created` audit row in the same transaction, carrying the author, the original `createdAt` and `publishedFromDraft`; no audit row for edit, cancel, delete (D101).                                                                                                                                                                                                                                                                                                                                                                                           |
