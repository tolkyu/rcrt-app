## Lighthouse closure re-check — 2026-11-05

**APPROVED.** Reviewed pinned development-only `lighthouse@13.6.0`, its lockfile/package/CI changes, and `tests/perf/lighthouse*.ts`. This adds no application authentication path or production dependency.

- The authenticated persistent Chrome profile is created by `mkdtemp` under ignored `.cache`; the CDP listener uses an ephemeral `127.0.0.1` port. Targets are the five fixed local Foundation routes, and the existing sign-in helper refuses a non-loopback Supabase origin. No hosted call was made during review.
- Lighthouse tracing is disabled. Saved success/failure artifacts contain numeric audit samples, route/device/version, budgets and generic status codes only. Full Lighthouse reports, headers/cookies, request bodies, screenshots and the authenticated profile are not uploaded.
- Review found that a browser-close or artifact-write error could bypass profile deletion. Fixed before approval: nested `finally` blocks always attempt removal, with the resolved target required to remain below `.cache`; failed cleanup still fails the run.
- Independent `audit:check` after installation passes: **zero production advisories, 48 tooling advisories**, with no new high/critical exception or widened path. Lighthouse-budget and dependency-policy unit tests also pass **17/17**. The existing exact advisory/module/severity/path policy remains authoritative. Final Lighthouse measurements are performance evidence owned by the orchestrator, not a security result.
